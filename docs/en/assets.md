# Assets

[Русский](../ru/assets.md) · English

Everything the game loads at runtime lives in `assets/`. There are 148 PNG
files and 22 OGG files at the time of writing, all addressed by paths that start
with `assets/`, for example `assets/tex/decor/regular/rack/rack_0.png`.

On Android these paths are packed into the APK; `core::asset::load_bytes`
strips the `assets/` prefix before asking `AAssetManager`. Never build a path
from `std::env` or an absolute location — always go through `core::asset`.

## Atlases

A texture is either a single image or a grid. The grid size is stored as
`texture_count = [cols, rows]` and the current frame as
`texture_frame = [col, row]`; `0,0` is the top-left cell. UVs are shrunk by
`TEXEL_EPSILON` to avoid sampling the neighbouring frame.

Known atlas sizes:

| Texture | Grid |
|---|---|
| `map/grass.png` and seasonal variants | 4×6 |
| `map/floor.png` | 3×3 |
| `map/wall.png` | 5×5 |
| `decor/regular/shop_door/shop_door.png` | 2×2 |
| `decor/regular/rack/rack.png`, `box/box.png` | per-object animation frames |

Animation frames are ordinary atlas columns: the game advances
`current_frame` and reads `frame_paths[i]` when a texture consists of separate
files (`rack_0.png`, `rack_1.png`, …).

## Sized paths

One texture can cover several cells without being sliced: append `@WxH` to the
path, for example `assets/tex/decor/light/big_lamp.png@1x2`. `Sprite::
split_sized_path` takes the suffix after the **last** `@`, so a file name may
contain `@` itself. Invalid sizes (`@0x1`, `@2x`, `@-1x2`) are ignored and the
texture is drawn at its natural size.

## Characters

Each character directory contains three files: idle and two walk frames
(`player.png`, `player_walk_1.png`, `player_walk_2.png`). Shoppers use the same
pattern with `bob` and `sasha`; `ShopperManager` picks one of the three sets at
random. Walk frames are swapped every `walk_anim_interval` seconds.

## Cursor and mode icons

`assets/tex/ui/cursor/` holds one cursor per mode (`move`, `interact`, `build`,
`delete`) plus an error variant. `CURSOR_TEX` and `MODE_ICON_TEX` in
`core/constants.rs` are indexed by the mode number, so adding a mode means
adding two textures and one constant.

## Sounds

`AudioEngine` scans `assets/sounds/` through `list_dir` and decodes the OGG
files with rodio. Names are used directly: `play("click")` looks for
`click.ogg`. Special cases:

- `play_music("music")` loops a track; `stop_music` stops it;
- `play_ambient` for weather loops (`rain.ogg`), stopped with `stop_ambient`;
- missing files are skipped silently, so a missing sound never crashes a scene.

Sound effects are generated by `assets/scripts/gen_sounds.py`; music tracks are
authored separately.

## Weather particles

There are no snow/rain PNG files. `WeatherFx` creates 4×4 white pixels for snow
and 2×16 light-blue pixels for rain with `Texture::from_rgba` at runtime, and
caches the sprite by a synthetic key (`"weather/snow"`). This keeps the asset
folder clean and makes the particles resolution-independent.

## Adding an asset

1. Put the file under the right category directory, `snake_case` name.
2. If it is an object, add an entry to `ALL_OBJECTS` with the texture path,
   atlas size and price.
3. If it is an inventory item, add its icon to
   `assets/tex/ui/icon_slots/icon_slots_object/<category>/`.
4. Run `cargo test`: `every_catalog_object_has_a_resolvable_icon` checks that
   every catalogue object has a readable icon, and map token tests check atlases.
5. Update this page if you added a new directory.
