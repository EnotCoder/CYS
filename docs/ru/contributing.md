# Участие в разработке

[English](../en/contributing.md) · Русский

## Перед изменениями

- Прочитай [architecture.md](architecture.md) — раскладка на 12 папок
  намеренная.
- Если меняешь картинку — [rendering.md](rendering.md); логику предметов —
  [ecs.md](ecs.md); баланс — [scripts.md](scripts.md).
- Перед первым изменением прогони `cargo test`, чтобы знать исходное
  состояние.

## Правила модулей

- В `src/` ровно 12 папок верхнего уровня. Не добавляй тринадцатую без
  серьёзной причины; почти всё укладывается в существующие модули.
- Новый файл объявляется в родительском `mod.rs` и, если он часть публичного
  API, реэкспортируется там же.
- `lib.rs` объявляет модули через `#[path = "../<модуль>/mod.rs"]`; сохраняй
  этот шаблон.
- Блоки `impl` одного типа живут в одном файле. Trait-impl нельзя разнести по
  подмодулям, поэтому планируй заранее.
- При переносе файлов: сначала переместить, потом обновить все `use`, потом
  собирать.

## Стиль кода

- Никаких комментариев на тривиальном коде. Комментарий объясняет *почему*, а
  не *что*.
- Комментарии и сообщения `assert!` — по-русски; идентификаторы и код — на
  английском.
- Группируй импорты: `use crate::{A, data::B};`.
- При переименовании используй `replaceAll`, а не множество точечных правок.
- Держи функции короткими настолько, чтобы побочные эффекты читались по имени.
  Если функция и меняет ECS, и рисует UI — раздели.
- SPDX-заголовок в новых файлах:

```rust
// SPDX-License-Identifier: GPL-3.0-or-later
// Copyright (C) 2026 EnotCoder
```

## Правила ECS

- Сущности создаются только через `create_sprite`, `add_group_object` или
  `add_ui`/`add_ui_sized`.
- Каждый новый компонент и ресурс регистрируется в `EcsAdapter::new`.
- Рендер не запрашивает `specs` напрямую; только через
  `get_sprites_by_layer`.
- Предикаты размещения остаются чистыми (`can_place_at`), побочные эффекты —
  в `data::placement`.
- Многоклеточные объекты идут через группы, а не через собранные руками списки
  сущностей.

## Правила рендера

- Новый слой требует: константу `Z_*`, список спрайтов в `Scene::sprites`,
  параметр в `core::render` и место в прозрачном или непрозрачном проходе.
- Всё с альфой — в прозрачный проход; всё ниже `Z_MAP` обязано быть
  непрозрачным.
- Любая структура, общая с WGSL, должна совпадать по `std430`, включая
  padding (см. `LightData`, 64 байта).
- Пиксель-арт использует `FilterMode::Nearest`; не добавляй `Linear` для
  спрайтов.

## Правила ассетов

- Пути всегда начинаются с `assets/` и читаются через `core::asset`.
- Иконки объектов — в `assets/tex/ui/icon_slots/icon_slots_object/<категория>/`.
- Новые текстуры следуют именованию: `snake_case`, кадры `_0`, `_1` или
  `_walk_1`, `_walk_2`.
- После добавления объекта запусти `cargo test`: тесты иконок и каталога
  скажут, чего не хватает.

## Правила документации

Документация — часть сборки. Меняя код, проверь, не устарела ли страница:

| Изменение | Обновить |
|---|---|
| новый/удалённый/переименованный `.rs` | `docs/{ru,en}/source-map.md` |
| новый модуль или шаг кадра | `docs/{ru,en}/architecture.md` |
| новый слой, пайплайн, uniform | `docs/{ru,en}/rendering.md` |
| новый компонент, ресурс, правило групп | `docs/{ru,en}/ecs.md` |
| баланс, покупатель, сезон, экономика | `docs/{ru,en}/gameplay.md` + `scripts.md` |
| поле сохранения, токен карты, настройка | `docs/{ru,en}/world-format.md` |
| новый каталог ассетов или правило имён | `docs/{ru,en}/assets.md` |
| команда сборки, цель, профиль | `docs/{ru,en}/build.md` |
| новый набор тестов или заготовка | `docs/{ru,en}/testing.md` |

Русский текст — основной, английский — перевод. Проза может быть живой, но
блоки кода копируй дословно: тест документации сравнивает их побайтово. После
правок запусти:

```sh
cargo test docs
```

## Чек-лист PR

- [ ] `cargo test` проходит;
- [ ] в диффе нет `target/`, `worlds/` и локальных изменений `settings.json`;
- [ ] у новых файлов есть SPDX-заголовок;
- [ ] новые пути начинаются с `assets/`;
- [ ] документация обновлена по таблице выше;
- [ ] если изменение видно в игре — сделан ручной smoke-тест;
- [ ] не осталось отладочных принтов;
- [ ] сообщение коммита описывает поведение, а не файлы (`add buy
  confirmation dialog`, а не `update shop.rs`).
