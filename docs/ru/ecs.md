# ECS

[English](../en/ecs.md) · Русский

CYS использует [`specs`](https://docs.rs/specs) 0.18, но только как хранилище:
`Dispatcher` и расписания нет. Геймплей вызывает обычные функции из
`GameScene::update`, а ECS просто держит сущности и отдаёт их рендеру.
`EcsAdapter` (`src/ecs/adapter/mod.rs`) — единственный фасад над
`specs::World`.

## Чем владеет адаптер

| Поле | Назначение |
|---|---|
| `world` | компоненты и ресурсы |
| `sprite_cache` | GPU-спрайты по ключу `sprite_cache_key` |
| `texture_cache` | декодированные текстуры по базовому пути (без `@WxH`) |
| множества позиций | поиск сущности по клетке (`map_entities`) |

`EcsAdapter::new()` один раз регистрирует все компоненты и ресурсы. Добавил
новый компонент — зарегистрируй его там же, иначе
`world.write_storage::<T>()` паникует в рантайме.

## Создание сущностей

Есть ровно три разрешённых входа; собирать `Transform` + `SpriteComponent`
руками не надо:

| Вызов | Что создаёт |
|---|---|
| `ecs::factory::create_sprite` | одну спрайт-сущность: `Transform`, `SpriteComponent`, `Rotation` |
| `EcsAdapter::add_group_object` | N сущностей многоклеточного объекта со сдвигом кадра |
| `EcsAdapter::add_ui` / `add_ui_sized` | UI-спрайты в UI-пространстве (`map_size = 1.0`) |

Спрайт — это квад с текстурой, кадром атласа (`[col, row]`), размером атласа
(`[cols, rows]`), масштабом и альфой. `Sprite::split_sized_path` позволяет
писать `path.png@2x2`, чтобы растянуть один тайл на площадь 2×2.

## Компоненты и ресурсы

| Тип | Вид | Смысл |
|---|---|---|
| `Transform` | компонент | `position`, `scale`, `rotation` |
| `SpriteComponent` | компонент | путь, кадр, атлас, альфа |
| `Rotation` | компонент | вектор поворота |
| `ObjectTag` | компонент | имя объекта (`rack`, `cassa`, …) для геймплея |
| `FoodStorage` | компонент | `food_count`, `max_food` |
| `GroupComponent` | компонент | id группы и смещение клетки внутри объекта |
| `FenceComponent` | компонент | ориентация забора |
| `ShopperTag` | компонент | маркер, по которому открывается дверь |
| `GroupInfoResource` | ресурс | id группы → сущности, размер, имя |
| `Money`, `TotalFood` | ресурс | счётчики экономики |
| `BusyCassas` | ресурс | кассы, занятые покупателями |
| `BasementPlaced` | ресурс | существует ли вход в подвал |
| `ShopOwned` | ресурс | купленные товары магазина |
| `Season` | ресурс | `Summer`, `Spring`, `Autumn`, `Winter` |
| `DoorState`, `DoorProgress` | ресурс | состояние и кадр анимации двери |

## Данные для рендера

`get_sprites_by_layer(bounds)` один раз проходит по storage на слой и
возвращает восемь `Vec<SpriteRenderData>`: карта, ковры, свет, декор, NPC,
погода, курсор, UI. `SpriteRenderData` — плоская структура (позиция, поворот,
путь, кадр, атлас, масштаб, альфа): ни типов `specs`, ни заимствований,
передавать в рендер безопасно.

Отсечение происходит здесь: спрайты вне `bounds` отбрасываются, а спрайты с
нулевой альфой — тоже. Сверх этого `update_object_textures` меняет кадры
коробки/стеллажа по количеству еды, а `update_fence_textures` выбирает кадр
забора по соседям.

## Многоклеточные объекты

`add_group_object` режет объект W×H на W·H сущностей, по одной на клетку, с
`GroupComponent { group, offset }` и кадром, сдвинутым на смещение. Рендер
остаётся глупым: каждая клетка — обычный спрайт.

`delete_group` удаляет все сущности группы. `find_group_at_position`
возвращает объект под курсором с фиксированным приоритетом: декор важнее
света, свет важнее ковра. Именно поэтому лампа может стоять на ковре, а
стеллаж — на полу.

## Превью курсора

Курсор — обычный спрайт на `Z_CURSOR`. `update_cursor_preview` строит
полупрозрачного «призрака» объекта с его настоящими кадрами атласа и
переключается на маркер ошибки, когда ставить нельзя. `clear_cursor_preview`
его убирает. Призрак — сущность, поэтому идёт тем же путём рендера, что и всё
остальное.

## Правила размещения

Правила разделены на два уровня:

- `ecs::placement::can_place_at` — чистая проверка: категория клетки,
  конфликт категорий, требования пола/стены/травы;
- `data::placement::{add, remove}` — побочные эффекты: деньги, возврат,
  пересчёт стен, `FoodStorage`, `BasementPlaced`, звуки.

Чистая проверка дешево тестируется: `src/tests/placement_rules.rs` собирает
ECS без GPU и проверяет оба направления.

## Почему без систем

`Dispatcher` из `specs` добавил бы модель параллельного планирования без
выгоды: в игре активна одна сцена и тик строго последовательный. Обычные
функции проще отлаживать и тестировать, а `GameScene` сам задаёт порядок
(ввод → экономика → NPC → день/ночь → данные рендера).

Плата за это — дисциплина: каждый новый компонент надо зарегистрировать, а
каждый новый слой — провести через `Scene::sprites` и `core::render`. За этим
следят [карта исходников](source-map.md) и тесты.
