# Рендеринг

[English](../en/rendering.md) · Русский

CYS рисует напрямую через `wgpu 30`: без движка и без стороннего
спрайт-батчера. Весь рендер — примерно тысяча строк в `src/core/`, и устроен
он намеренно скучно: один GPU-контекст, два пайплайна, три прохода.

## GPU-контекст

`WgpuApp` (`src/core/init.rs`) владеет всем долгоживущим:

- `Instance`, `Surface`, `Adapter`, `Device`, `Queue`;
- uniform-буфер `Size` (мир) и `UiUniforms` (UI);
- один dynamic storage buffer под uniform'ы спрайтов;
- буфер света и `DepthBuffer`;
- оба пайплайна и их bind group.

Создаётся один раз в `resumed`. На Android `resumed` вызывается повторно после
возврата из фона; контекст переиспользуется, пересоздаётся только surface.
Полная пересборка контекста ломала эмулятор ошибкой
`Failed to find ColorBuffer`.

## Пайплайны

| Пайплайн | Для чего | Смешивание | Тест глубины |
|---|---|---|---|
| `render_pipeline` | тайлы карты | alpha blend | `LessEqual` |
| `transparent_pipeline` | ковры, свет, декор, дверь, NPC, погода, курсор | `ALPHA_BLENDING` | `Always` |

Раскладка вершин общая: позиция `[x, y, z]` и `uv`. Глубина —
`Depth32Float`, пересоздаётся при resize. Прозрачный пайплайн игнорирует
глубину осознанно: игровые слои уже упорядочены по `z`, а спрайты с альфой не
должны перекрывать друг друга по глубине.

## Один кадр, три прохода

1. **Карта** — `render_pipeline`, очистка глубины. Тайлы непрозрачны и
   закрывают экран.
2. **Прозрачный** — `transparent_pipeline`, по одному draw на батч в порядке
   z. Спрайты с `alpha == 0` (например покупатель внутри проёма двери) вообще
   не отправляются.
3. **UI** — отдельные uniform'ы с `night_factor = 0`, поэтому HUD не темнеет
   от цикла день/ночь.

## Слои

Меньший `z` рисуется раньше. Значения — в `src/core/constants.rs`:

```
Z_MAP=0.0 → Z_CARPET=1.0 → Z_LIGHT=1.2 → Z_DECOR=1.5 (Z_DOOR)
→ Z_NPC=1.8 → Z_WEATHER=1.9 → Z_CURSOR=2.0
→ Z_UI=3.0 → Z_UI_TEXT=3.005 → tooltips → dialogs
```

Дверь живёт на `Z_DECOR`, а не на `Z_MAP`, потому что её открытый кадр
прозрачный: в непрозрачном проходе получилась бы чёрная дыра. При этом она
обязана быть ниже `Z_NPC`, чтобы створка не закрывала покупателя.

Подслои UI: `Z_UI_TEXT` 3.005, фон тултипа 3.01 / текст 3.02, затемнение
диалога 3.03 / панель 3.035 / текст 3.04.

## Батчинг и кэш спрайтов

Геймплей не создаёт GPU-объекты. `get_sprites_by_layer` возвращает плоские
`SpriteRenderData` (позиция, поворот, путь к текстуре, кадр, размер атласа,
масштаб, альфа). Дальше `render_group`:

1. строит ключ через `sprite_cache_key` = слой + путь + кадр + атлас +
   масштаб (дробное хешируется через `to_bits`);
2. берёт готовый `Sprite` из `EcsAdapter::sprite_cache` или создаёт его один
   раз;
3. пишет все `Uniforms` батча одним `queue.write_buffer`, дополняя каждую
   32-байтовую структуру до `min_storage_buffer_offset_alignment`;
4. делает один draw на спрайт с dynamic offset.

Вершинный и индексный буферы общие (`QUAD_INDICES`), поэтому спрайт стоит
один 32-байтовый слот uniform'а, а не четыре вершины.

`MAX_DYNAMIC_SPRITES` равен 65 536, но реальный лимит —
`max_storage_buffer_binding_size / alignment`. На AMD RADV лимит биндинга
64 КБ, поэтому за кадр может поместиться заметно меньше спрайтов; `init.rs`
урезает число через `min`, а `render_group` останавливается при заполнении
буфера, а не паникует.

## Текстуры

`Texture` = `wgpu::Texture` + view + sampler. Важны два конструктора:

- `from_path` — декодирует PNG/JPEG через `image`, заливает на GPU, при
  отсутствии файла подставляет `dev_tools/null.png` (битый ассет видно, но
  игра не падает);
- `from_rgba` — сырые пиксели для текста и UI.

Атласы — обычные сетки: `texture_count = [cols, rows]`, `texture_frame =
[col, row]`, а `TEXEL_EPSILON` поджимает UV на долю текселя, чтобы кадры не
«текли» друг в друга. Фильтрация — `Nearest` осознанно: это пиксель-арт, а
линейная фильтрация превращает его в мыло.

Виртуальные пути `tex.png@WxH` растягивают одну текстуру на W×H клеток;
`Sprite::split_sized_path` разбирает суффикс после **последнего** `@` и
игнорирует некорректные размеры.

## Свет и день/ночь

World-uniform'ы несут `map_size` (зум), `aspect`, смещение камеры,
`night_factor` и `light_count`. Источники света — записи `LightData`
(`position`, `color + intensity`, `radius`) в storage-буфере. Шейдер
добавляет радиальный вклад каждого источника и смешивает результат с
`night_factor`.

`LightData` обязан быть ровно 64 байта, чтобы совпасть с WGSL `std430`. Если
Rust-структура меньше, `lights[1..]` читаются по неверному смещению и дают
мусор — классический баг «вторая лампа не светит».

UI-проход использует `UiUniforms` с `night_factor = 0` и `light_count = 0`,
поэтому интерфейс читается ночью. Эта же структура зеркалится в глобальный
`UI_UNIFORMS`, из которого хит-тесты UI переводят NDC в единицы UI.

## Отсечение и подгонка UI

`sprites(bounds)` получает видимый прямоугольник мира и выбрасывает всё за
его пределами ещё до батчинга. `ui_fit_scale` и `ui_visible_half_h` считают
масштаб в `[UI_MIN_SCALE, 1.0]`, чтобы весь UI-бокс помещался при любом
соотношении от 4:3 до 20:9; `ui_top_offset`/`ui_bottom_offset` прижимают HUD и
хотбар к краям экрана с отступом `UI_EDGE_MARGIN`.

## Частые грабли

- **Новый слой** — добавь константу, список `SpriteRenderData`, привязку в
  `Scene::sprites` и передачу в `render`; забытый шаг даёт невидимые спрайты
  без единой ошибки.
- **Кадр атласа** — выход за `[col, row]` сэмплит вне текстуры. Тест
  `every_map_token_resolves_to_an_in_bounds_atlas_frame` ловит токены карты.
- **Прозрачный объект ниже `Z_MAP`** — попадёт в непрозрачный проход и
  потеряет альфу.
- **Размер uniform'а** — любая структура, общая с WGSL, должна совпадать по
  `std430`-выравниванию, а не только по порядку полей.
