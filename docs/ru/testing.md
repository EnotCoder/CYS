# Тесты

[English](../en/testing.md) · Русский

Тесты лежат в `src/tests/` и компилируются в библиотеку под `#[cfg(test)]`.
Они быстрые и не требуют GPU, окна или звукового устройства: рендер и ввод
представлены обычными данными и фейковым источником ввода.

```sh
cargo test
cargo test docs
cargo test -- --nocapture
```

`cargo test docs` запускает только проверки документации. Один тест можно
выбрать по имени, например `cargo test door`.

## Наборы

| Файл | Что проверяет |
|---|---|
| `src/tests/mod.rs` | цикл режимов, текстовый ввод, чистые функции, масштаб UI, токены карты, каталог |
| `src/tests/helpers.rs` | общие заготовки: `new_ecs`, размещение, `FakeInput`, перевод UI в пиксели |
| `src/tests/data_integrity.rs` | константы, `ALL_OBJECTS`, баланс, день/ночь, кэш спрайтов, настройки |
| `src/tests/placement_rules.rs` | `can_place_at`, `add`, `remove`: категории, конфликты, возврат, стены, подвал |
| `src/tests/group_tests.rs` | раскладка групп, кадры атласа, слои, `find_group_at_position`, удаление |
| `src/tests/npc_tests.rs` | состояния покупателя, движение, еда/конфеты, кассы, маршруты, фейд, дверь |
| `src/tests/input_tests.rs` | зум, хит-тесты UI, слайдер, прокрутка магазина, имя мира, затухание двери, погода |
| `src/tests/anim_tests.rs` | `PanelAnim` открытие/закрытие/отмена и текстовые спрайты |
| `src/tests/docs.rs` | пары RU/EN, полнота карты, одинаковые блоки кода, живые ссылки |

Всего около 90 тестов. Это обычные `#[test]`-функции, а не системы `specs`,
поэтому падение указывает на имя функции, а не на расписание.

## Как писать тест без GPU

`helpers::new_ecs` собирает `EcsAdapter` с зарегистрированными компонентами,
но без device и queue. Всё, что касается только ECS — размещение, группы,
экономика, поиск пути, состояния NPC — так и тестируется. Используй
`create_sprite`/`add_group_object` ровно как игровой код.

`FakeInput` реализует `InputSource` и позволяет сказать: «в этом кадре нажата
левая кнопка, курсор в NDC (x, y), колесо прокрутилось на 3». Так покрыты зум,
слайдеры, прокрутка магазина и хит-тесты UI.

Ассеты читаются через `core::asset`, поэтому тесты иконок и карт используют
реальные файлы репозитория. `include_str!("../../assets/map.txt")` применяется
там, где зависимость на этапе компиляции допустима.

Правила:

- никаких sleep и реального времени: `dt` передаётся явно;
- никакой случайности в проверках: `rand01` детерминирован, а тесты NPC
  используют фиксированные позиции;
- никаких GPU-вызовов: если функции нужны `device`/`queue`, тестируй чистую
  часть вокруг;
- сообщения `assert!` пишутся по-русски, как и весь код.

## Тесты документации

`src/tests/docs.rs` — часть `cargo test` и контракт документации:

1. у каждого `docs/ru/*.md` есть пара `docs/en/*.md`, и наоборот;
2. каждый путь `src/**/*.rs` упомянут в обоих `source-map.md`, а каждый
   упомянутый там путь `src/...` существует;
3. блоки кода в RU и EN версии страницы совпадают;
4. все относительные ссылки и картинки Markdown указывают на существующие
   файлы.

Поэтому новый модуль надо добавлять в карту исходников тем же изменением, а
примеры кода в переводах копировать дословно, а не переформатировать.

## Ручной smoke-тест

Перед релизом запусти игру и проверь:

- новый мир → туториал → поставить коробку/стеллаж/кассу → открыть магазин;
- покупатель входит, покупает, платит, выходит через дверь;
- `Esc` останавливает аренду и день/ночь;
- покупка в магазине переживает `Ctrl+S` и перезагрузку из меню;
- Android: Back закрывает панели, щипок зумит, drag одним пальцем двигает
  камеру только в режиме `move`.

## Что не покрыто

- вывод GPU (нет golden-image тестов);
- воспроизведение звука;
- Android JNI и поведение `EditText`;
- взаимодействия на реальном времени (аренда через 60 с проверяется через
  значения, а не ожиданием).

Это проверяется руками; держи ручной чек-лист коротким и повторяемым.
